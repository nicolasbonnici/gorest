# DTOs & Field Control

GoREST automatically generates Data Transfer Objects (DTOs) from your model structs, giving you fine-grained control over which fields are accessible in different operations.

## The `dto` Struct Tag

Control field visibility with the `dto` struct tag:

```go
type Todo struct {
    Id        string     `json:"id" db:"id"`
    UserId    *string    `json:"user_id" db:"user_id" dto:"read"`  // Read-only
    Title     string     `json:"title" db:"title"`
    Content   string     `json:"content" db:"content"`
    CreatedAt *time.Time `json:"created_at" db:"created_at"`
}
```

## Generated DTOs

For each model, three DTOs are generated:

### CreateDTO (POST)

Used for creating new records. Automatically excludes:
- `id` - Generated by database
- Fields marked `dto:"read"` - Server-controlled fields
- Timestamp fields like `created_at`, `updated_at`

```go
type TodoCreateDTO struct {
    Title   string `json:"title"`
    Content string `json:"content"`
}
```

### UpdateDTO (PUT/PATCH)

Used for updating existing records. Automatically excludes:
- `id` - Immutable primary key
- Fields marked `dto:"read"` - Server-controlled fields
- Timestamp fields like `created_at`

```go
type TodoUpdateDTO struct {
    Title   string `json:"title"`
    Content string `json:"content"`
}
```

### ResponseDTO (GET)

Used for API responses. Includes all fields, respecting visibility rules.

```go
type TodoDTO struct {
    Id        string     `json:"id"`
    UserId    *string    `json:"user_id"`
    Title     string     `json:"title"`
    Content   string     `json:"content"`
    CreatedAt *time.Time `json:"created_at"`
}
```

## Tag Values

| Tag | Behavior |
|-----|----------|
| `dto:"-"` | Exclude from all DTOs (sensitive data) |
| `dto:"read"` | Only in responses (server-controlled) |
| `dto:"write"` | Only in create/update (client input only) |
| `dto:"read,write"` | Include in all (default behavior) |
| *(no tag)* | Include in all (same as `read,write`) |

## Examples

### Read-Only Fields

Fields that should only be set by the server:

```go
type User struct {
    Id        string     `json:"id" db:"id"`
    Email     string     `json:"email" db:"email"`
    Password  string     `json:"-" db:"password" dto:"-"`  // Never exposed
    IsAdmin   bool       `json:"is_admin" db:"is_admin" dto:"read"`  // Server-only
    CreatedAt *time.Time `json:"created_at" db:"created_at" dto:"read"`
}
```

### Write-Only Fields

Fields that clients can set but aren't returned:

```go
type PasswordReset struct {
    Token       string `json:"token" db:"token" dto:"write"`  // Input only
    NewPassword string `json:"new_password" dto:"write"`      // Input only
    UpdatedAt   time.Time `json:"updated_at" db:"updated_at" dto:"read"`
}
```

## Best Practices

1. **Always exclude passwords**: Use `json:"-"` and `dto:"-"`
2. **Mark server-controlled fields as read-only**: `dto:"read"`
3. **Use semantic field names**: `user_id` becomes `user` in JSON-LD
4. **Consider data minimization**: Only expose necessary fields
